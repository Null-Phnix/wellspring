# Deploying Wellspring

One plain CloudFormation template defines the AWS resources in `ca-central-1`.
It avoids an additional SAM build dependency and leaves the public demo
reproducible with the installed AWS CLI and Python. `infra/template.json` is
generated by `scripts/make_template.py`.

## Resources and boundaries

- The data bucket and static site bucket block public S3 access and use encryption
  and versioning. CloudFront can read only the site bucket through origin access
  control. The API role can read only `published/*` from the data bucket.
- API Gateway HTTP API invokes the read-only API Lambda. Its stage limits traffic
  to two requests per second with a burst of five. This is a cost guard, not a
  spending cap or a denial-of-service guarantee.
- A separate ingestion Lambda can read/write the published data, raw source and
  history prefixes. It has no public route. EventBridge Scheduler invokes it at
  `07:00 America/Edmonton`, so Mountain daylight saving changes are handled.
- The schedule starts disabled. Enable it only after the data and real Lambda
  code are deployed and a manual ingestion check succeeds.
- Logs expire after seven days. No VPC, NAT gateway, paid data or model calls are
  used. Free-tier eligibility depends on the account. Josii owns the $5 budget
  alarm; that alarm is not created by this template and is not a spending cap.

The scheduler timezone property and Python 3.13 runtime are documented by
[AWS Scheduler](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-scheduler-schedule.html)
and [AWS Lambda](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtimes.html).

## Reproduce

The owner-authorized AWS values are loaded inside the CLI subprocess from the
local configuration file. They are never copied to Lambda environment variables,
source files, build archives, logs or deployment receipts. Lambda uses scoped IAM
roles. Run commands from the repository root; use the project's Python environment
for tests and data preparation.

```bash
python3 scripts/make_template.py
python3 scripts/aws_task.py cloudformation validate-template --template-body file://infra/template.json
python3 scripts/deploy.py bootstrap
python3 scripts/deploy.py status
PYTHONPATH=. python3 scripts/build_data.py
PYTHONPATH=. python3 scripts/enrich_export.py
python3 -m pytest -q
python3 scripts/deploy.py publish --data output/published
python3 scripts/deploy.py status
python3 scripts/deploy.py verify
```

Bootstrap creates the infrastructure with a 503 placeholder. `publish` uploads
an immutable code ZIP and the verified export, then updates the same template
with that code key. It does not claim the placeholder is a working application.
Wait for `CREATE_COMPLETE` or `UPDATE_COMPLETE` between phases. The initial
backfill script explicitly selects August 2026 and September 1-26, 2026; it is a
reproducible sample, not the full January-to-current backlog.

`publish` leaves the schedule disabled. After endpoint checks and a successful
manual call of the ingestion function:

```bash
python3 scripts/deploy.py enable-schedule
```

The two-step process avoids an external artifact bucket: the template's data
bucket holds the immutable deployment package under `artifacts/`. A rerun of
`publish` requires a completed stack, disabled scheduler, committed runtime
source and exact local export hash. It refuses losing a loaded source date and
uses an ETag precondition for the manifest. `publish-receipt.json` means update
requested only; `verify` checks UPDATE_COMPLETE and both deployed Lambda code
hashes before writing `verified-deployment.json`. Runtime
publication writes an immutable export and historical manifest before switching
the current manifest with an S3 ETag precondition, so overlapping ingestions
cannot silently overwrite each other's newer snapshot. Retries of unchanged
source bytes keep the original record provenance.

## API and web handoff

`status` prints the API URL, CloudFront domain and site/data bucket names. Use
`docs/API-CONTRACT.md` for routes and response shapes. Nabu owns the Angular
production configuration and static-site upload. This backend deployment does
not make an empty site bucket into a completed frontend. CloudFront rewrites
403/404 to `/index.html` for client-side deep links once that file exists.

## Recovery

A failed source fetch or parse preserves valid previously published dates and
records the failed retry. A corrupt published export fails closed at the API.
Lambda refreshes the data snapshot after 60 seconds. For a rollback, republish
an earlier complete manifest and its referenced export, and update `CodeKey` to
the previously recorded immutable bundle key. Keep the daily schedule disabled
while investigating publication failures.

Deleting the owned stack removes the API, functions and distribution, but both
buckets are retained to preserve source data. Their contents may continue to
incur small storage charges. Bucket deletion is a separate explicit cleanup,
not an automatic side effect of rollback. Do not delete unrelated AWS resources.
